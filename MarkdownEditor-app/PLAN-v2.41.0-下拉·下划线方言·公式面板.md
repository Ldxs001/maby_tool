## 0. 一句话

**公式面板是 LaTeX 的可视化输入层：往格子里填，出来就是 LaTeX，插进编辑区是 `$…$`，预览区 KaTeX 渲染——没有公式对象模型；面板槽位递归，任何槽可嵌套任何范式节点（如分数的分母里放四角标）。面板按两类组织：通用范式三个（四角标 / 分数 / 容器），各一套界面覆盖多种命令；特殊形两个（根号 / 帽线），结构线是字形的一部分，只能单独做。下划线用 `++`，`++{y x n}++` 把 `y`（只有 `0` 空 / `□` 方框）重复 `n` 次，只出单线。六组格式按钮右侧各挂三角下拉。下划线与批注永不同屏，不必处理。**

## 2. `++` 语义规格

### 2.1 两种形态

| 形态 | 写法 | 输出 | 说明 |
|---|---|---|---|
| 普通 | `++文本++` | `<u class="uline">文本</u>` | 内容参与加粗/斜体/删除线/上下标/链接 |
| 重复 | `++{y x n}++` | `<u class="uline">y 重复 n 次</u>` | 内容不参与任何行内语法，纯字面 |

只有单线。线型不设维度，`=` 不做（§3.1）。

### 2.2 单元 `y` 只有两种

`y` **不是任意内容，也不是符号大全**。它只是"要被重复的那一个东西"，只有两种：

| `y` | 含义 | `n=3` 时 | 用途 |
|---|---|---|---|
| `0` | **空字符**（一个正文字宽的空白，输出 `U+00A0`） | 三字宽空白 + 下划线 = 三字长的填空横线 | 让人往上写字 |
| `□` | 空心方框 `U+25A1` | `□□□` + 下划线 = 三个能装下当前字号的格子 | 填字格 |

**就这两种。** 上一版塞进 `■ ○ △ _` 是错的，全部撤回：

- `_`：下划线本来就由 `++…++` 自己提供，再拿下划线字符模拟一遍是自我重复，`y` 里根本不该有它；
- `■ ○ △`：没有真实场景，纯凑数。

`0` 不是数字零，是**空**的代号——`++{0 x 9}++` 输出九字宽空白横线，绝不会出现九个 `0`。集合外一律 fail-closed（原文保留），不猜、不扩展。

### 2.3 线型：只有单线

不做双线，理由与替代办法见 §3.1。样式就一条：

```css
u.uline{ text-decoration:underline; text-decoration-thickness:1px; text-underline-offset:1px; }
```

用 `text-decoration` 而不是 `border-bottom` 或背景渐变：它是 Word 导出时 `docx_export.py` 唯一认的那份样式（`:602`），换成别的就得给导出链再加一条识别分支，纯增维护面。

### 2.4 解析算法（确定性，无歧义）

```
正则：  ^\+\+\{(.)\s*[x×*]\s*(\d+)\}\+\+$
取值：  ① 单元：单个字符，必须在 §2.2 的集合内
        ② 分隔符：半角 x / 全角 × / 星号 *，三者等价；两侧空格任意
        ③ 次数 n：只认 1–200 的十进制整数
失败：  任一条不成立 → **整段原文保留**（fail-closed，与 @@ color 未闭合同口径）
```

因为单元限单字符，`0x9` / `0 x 9` / `□x9` / `□ x 9` 四种写法全等价，不需要贪婪回溯，也不需要"单元里含 x"的容错——那个问题随"受控集"一起消失了。

### 2.5 三个实现细节

| 细节 | 不做的后果 | 做法 |
|---|---|---|
| **空白转 NBSP** | `0` 展开成 9 个半角空格，HTML 折叠成 1 个 → 横线只有 1 字长 | 单元 `0` 直接输出 `\u00A0`，不走空格 |
| **n 上限 200** | `++{□x99999}++` 一次产 10 万节点，预览卡死 | 超限 fail-closed 原文保留 |
| **整段占位** | 展开出的 `□`／NBSP 若留在正文流里，会被后续行内规则（`*` `~` `[` 等）二次扫描，结果不可预期 | 重复形态整段 push 进 `toks` 占位（见 §2.6 步骤 A），一次成型 |

### 2.6 代码落点（`parseInline`，`:2267`）

现有行内规则顺序（改错位置就出 §2.5 第三条的 bug）：

```
2338  escapeHtml
2351  @@ color x{…}
2377  ^{…} 上标
2381  _{…} 下标
2394  图片
2435  链接
2439  **/__ 加粗
2440  */_ 斜体
2441  ~~ 删除线
2442  @@C 代码段还原
2443  toks 还原
2446  反斜杠转义还原
```

插入两处：

| 步骤 | 位置 | 做什么 | 为什么必须在这 |
|---|---|---|---|
| **A** | 在 `2377` 之前（escapeHtml 之后） | 扫 `++{…}++`，展开、转义、整段 push 进 `toks` | 必须在全部行内规则之前，展开产物才不会被二次扫描 |
| **B** | 在 `2441` 之后（`~~` 之后） | `\+\+([^+\n]+)\+\+` → `<u class="uline">$1</u>` | 必须在强调之后，内容才能享受 `**`/`~~`；已占位的 A 产物不会被 B 碰 |

`+++x+++` 的行为：A 不匹配，B 从第 2 个 `+` 起匹配 → `+<u class="uline">x</u>+`。fail-open 但无害，不特判。

**为什么带 `class="uline"` 而不是裸 `<u>`**：裸 `<u>` 只能吃浏览器 UA 默认的线宽与偏移，改不了厚度；带类后线宽/偏移由一处 CSS 定，预览、打印、Word 导出三处行为一致。而且将来若要给编辑区做语法高亮，类名是唯一能挂钩的锚点。

### 2.7 三处出口

| 出口 | 现状 | 要做的 |
|---|---|---|
| 预览 | 无（`++` 是新语法） | 渲染 `<u class="uline">`，样式见 §2.3 |
| 打印 / HTML 导出 | 克隆预览 DOM | 无需改动（`text-decoration` 天然打印，不会像背景线那样丢） |
| Word 导出 | `inlineStylesInto`（`:6653`）抄 `text-decoration` 计算值；`docx_export.py:602` 命中 `underline` → `run.font.underline = True` | **只有一处真坑**：`<u><strong>x</strong></u>` 时 strong 的计算值是 `none`（`text-decoration` 不继承、只传播绘制），文字挂在 strong 上 → Word 丢下划线。修法：导出前把 underline 强制下推到所有后代节点（不判 double，已不做） |

## 3. 三件事的定论

### 3.1 双下划线：不做

**跟你的判断一致，不做。** 三条理由，第一条是硬的：

| # | 理由 |
|---|---|
| 1 | **浏览器与 Word 的双线间距不是同一套**。Chromium 的 `underline double` 两条线实测间隔 3px（约 1/6 字号，随字体变），Word 的 `DOUBLE_LINE` 另有固定间距。要视觉对齐就得自己拼两层背景去画，那又落回"背景线打印会丢、Word 导出还得另认一套"的老问题——成本比看上去大得多 |
| 2 | **真实场景接近零**。双线在 Word 里是公文/正式表单的排版惯例；Markdown 写作里的填空线一律单线 |
| 3 | **多一个标记多一条链**：`=` 要多一个解析分支、一条 lint 边界、一条 docx 判定、一条回归用例。为 0 需求付这份维护费不划算 |

真需要双线怎么办：**导出到 Word 后选中那段文字改线型**。这一条就够，不值得为它动语法。

顺带把 `__` 的下场说清：`markdown-editor.html:2439` 已把 `__x__` 定义为**加粗**（CommonMark 口径），它既不能当定界符、也不能当单元。

`++` 本身不是自造：Markdown-it 的 `ins` 插件里 `++插入++` → `<ins>`，而 `<ins>` 的浏览器默认样式正是下划线。我们用 `<u>` 而非 `<ins>`，只因 `<ins>` 带"插入"语义会进无障碍树。

### 3.2 与批注：两区不相交，本来就不用管

**你这句话是对的，我该一开始就说：下划线只在预览区渲染，批注只在编辑区存在，两个 DOM 从来不同屏。** 上一版那一整节"同 y 对齐 / 谁盖谁"的推演是白做，已删。

| 事实 | 位置 |
|---|---|
| `++` 走 `parseInline`，只服务预览区 | `markdown-editor.html:2267` |
| 批注 `span[data-aid]` 只在 contenteditable 编辑区；编辑区只允许文本节点与本 span | `:4248` 注释、`:10613` `annWrap` |

所以「谁在上、谁盖谁」今天不存在，将来也不会自己冒出来。**不做任何预留 CSS、不改批注现有样式。** 万一哪天真给编辑区加 `++` 语法高亮（那是独立决定），到时再谈，现在写契约是空转。

唯一相关的既有事实，仅作记录、不动手：批注现在用 `border-bottom:2px dotted`（`:170-175`），锚在盒底，与 `text-decoration` 不锚同一处。若将来同屏会差 1～3px。**今天不改。**

其他行内功能的交互，逐条验过（这部分结论有效，保留）：

| 组合 | 结果 | 依据 |
|---|---|---|
| `@@ color r{++x++}` | ✅ 正常（color 在 `2351` 只包 span、不占位，`++` 规则后续仍能作用） | 代码顺序 |
| `~~++x++~~` | ✅ 正常（`~~` 在 `2441`，B 在它之后） | 同上 |
| `[++x++](url)` | ✅ 正常（链接只占位开标签，文字留在原地） | `:2435` |
| `++x++` 在代码段内 | ✅ 不动（`@@C` 已占位） | `:2275` |
| `++a｜b++` 在表格行内 | ❌ 半角 `\|` 会被切成两格（`**` 同样中招，属既有限制） | 块级表格切分 |
| `++x++` 跨行 | ❌ 不支持（B 的正则不跨换行） | 设计 |

### 3.3 范式划分：通用三个，特殊两个

上一版把分数和四角标合成"一个插槽范式"，**错了**。你说的两点都对：四角标与分数是**两种**通用范式，根号塞不进它们、必须单独。重新划：

**判据只有一条**：换参数就能覆盖多个命令的 → 通用范式；结构线本身是字形、换参数画不出来的 → 特殊形。

#### A 类 · 通用范式（一套界面，换参数覆盖多种）

| # | 范式 | 拓扑 | 换什么 | 覆盖 |
|---|---|---|---|---|
| **A1** | 四角标 | 中心格 + 左上 / 左下 / 右上 / 右下 | 开哪几个角、中心填什么 | `x^{2}`　`x_{i}`　`x^{2}_{i}`　`{}^{3}_{4}X`　`\sum_{i=1}^{n}`　`\int_{0}^{1}`　`\lim_{x\to0}` |
| **A2** | 分数 | 上格 / 中线 / 下格，竖直三段 | 中线开或关 | 开 → `\frac{a}{b}`；关 → `\binom{a}{b}`（自带圆括号，不依赖 A3） |
| **A3** | 容器 | 左符 + 内部（单行或网格）+ 右符 | 左右符、行列数、有无列线 | `\left(\right)` `\left[\right]` `\left\{\right\}` `\left|\right|` `\left\|\right\|` `pmatrix` `bmatrix` `vmatrix` `cases` |

**通用还需要增加什么 → 只加 A3 容器。** 理由是同一条判据：它也是换参数覆盖多个；不补它，括号、矩阵、分段要么没入口，要么每样单开一套，那才真叫乱。A1、A2 之外我没有别的通用范式要补——`\overset` / `\underset` 属于 B2（见下），不另开一套。

**A1 就是大运算符**：`\sum_{i=1}^{n}` 与 `{}^{3}_{4}X` 是同一个节点，只是中心格填 `\sum` 还是填 `X`。这一条上一版说对了，保留——但请注意，这**不等于**把 A1 和 A2 合并，那是两件事。

#### B 类 · 特殊形（结构线是字形的一部分）

| # | 特殊形 | 为什么 A1/A2/A3 表达不了 | 序列化 |
|---|---|---|---|
| **B1** | 根号 | √ 的钩与覆盖横线是连笔字形，不是"格 + 分隔线"；根指数还挂在钩的左外上方，也不在四角位置 | `\sqrt{x}`　`\sqrt[3]{x}` |
| **B2** | 帽线 | 符号压在内容**正中上方**（或正中下方），横向位置随内容宽度居中，既不是角、也不是中缝 | 上：`\overline{x}` `\vec{x}` `\hat{x}` `\tilde{x}` `\dot{x}` `\bar{x}` `\check{x}` `\breve{x}` `\acute{x}`，自定义符号走 `\overset{a}{x}`；下：`\underline{x}` `\underbar{x}`，自定义走 `\underset{a}{x}` |

**特殊还需要增加什么 → 只加 B2 帽线。** 它换一个符号参数就覆盖上表 11 条（含自定义的 `\overset` / `\underset`），但压线位置既不是角也不是中缝，A1/A2/A3 都拼不出来，所以归特殊。除此之外不再加：`\boxed`、`\cancel`、带文字的 `\underbrace` 场景少，先用手打，不设入口——**为单个符号建模板正是你反对的**。

#### C 类 · 字符板（不是范式）

希腊字母、运算符、关系符、箭头、大型符号：点一下插一个字符。没有格子、没有容器、没有结构线，所以不需要任何模板。**多，但不乱。**

#### 一句话对照

| 类别 | 按钮数 | 按钮 |
|---|---|---|
| 通用范式 | 3 | 四角标 `◱` / 分数 `a/b` / 容器 `(▦)` |
| 特殊形 | 2 | 根号 `√` / 帽线 `x̄`（含 `\overset` `\underset`） |
| 字符板 | 5 组 | 希腊 / 运算符 / 关系符 / 箭头 / 大型 |

## 5. 本地链接文件：现状是死路，必须先修服务端

> ⚠️ **本节已被 §11 推翻（2026-11-10 13:51 实测），V2 不得以本节为准。**
> ① 粘贴文件**并不插入普通 markdown 链接**，插入的是 low runner 数据点方言 `@@ MDE_… == rel}`；
> ② 该数据点在渲染区**本来就挂「打开」按钮**，走 `/api/open-ref` 用系统关联程序打开，一直可用；
> ③ 因此 V2 不是「从零造一条点得开的本地链接」，而是「给既有链路补一个选文件入口」。
> 本节 §5.2 / §5.3 的 `/file?path=` 端点方案**整体撤回**（主人要的是渲染区打开按钮，不是浏览器新标签页）。
> 「普通 `<a href>` 指向本地附件会 404」这一条实测仍然成立，所以 §11 明令**不产 `[名](rel)`**。

### 5.1 证据链（三条，缺一条结论都不成立）

1. **普通链接渲染成 `<a href target="_blank">`**（`:2435`）。点它 → WebView2 导航到 `http://127.0.0.1:<port>/<相对路径>`。
2. **根级静态兜底只服务工具目录**：`full.startswith(root)`，`root = HERE`（安装目录），且扩展名白名单只有 png/jpg/jpeg/webp/gif/svg/ico/css/js（`:2369-2377`）。文档的 `xxx.assets/a.pdf` 不在 `HERE` 下 → **404 not found**。
3. **`/api/open-ref` 有资产白名单**：`_within(c, assets)`，不在本文档 `.assets` 内直接报「文件不存在或不在本文档资产目录内」（`:3082`）。这条是**安全设计**（文档可被别人发给你，放开等于双击运行任意程序），不能为了功能拆掉。

**结论：现在没有任何一种写法的本地文件链接能点开。** 写绝对路径（方案 B）也点不开——白名单挡着。

### 5.2 三条路，我选 A

| 方案 | 做法 | 点击能否打开 | 可移植性 | 判断 |
|---|---|---|---|---|
| **A. 复制进 `.assets`** | 新增端点把选中文件复制进 `<doc>.assets/`，写相对路径 | ✅ 需同时新增 `/file?path=` 端点 | ✅ 文档随包带走 | **推荐** |
| B. 只写绝对路径 | `[名](C:\a\b.pdf)` | ❌ 白名单拒绝 | ❌ 换机即断 | 否决 |
| C. 每次问 | A 与 B 二选一弹窗 | 选 B 就打不开 | 一半 | 作为 A 的可选开关 |

### 5.3 配套必须新增的端点

```
GET /file?path=<相对路径>
  白名单：规范化后必须落在「本文档 .assets 目录」内（复用 _within）
  只读、Content-Type 按扩展名、Content-Disposition: inline
  非白名单内 → 404（不泄露存在性）
```

不新增这个端点，A 方案也只是"链接能看不能点"。

## 7. 公式面板

### 7.1 它到底是什么

**一句话定死：这是 LaTeX 的人类友好可视化输入层。面板里的每一个格子、每一条线，对应的就是一段 LaTeX 结构；填完序列化出 `$…$`，到此为止。**

**不对标任何外部软件。** "Word"这个词在本计划里只出现在一处：导出 .docx 时的映射（§9 风险表 R6/R7）。面板的布局、交互、节点模型全部由 LaTeX 本身的结构决定，与 Word 长什么样无关——借用的只是"点模板出格子、往格子里打字"这一种通用交互形式，这种形式不是哪家的专利。

用户在面板里做的事只有一件——往格子里填内容；面板交出来的东西也只有一件——**一段 LaTeX**。中间没有第三种格式。所以：

| 有 | 没有 |
|---|---|
| 格子、横线、√ 的钩——面板自己的 CSS | OMML、`m:oMath` —— 一个字节都不产 |
| 面板内部一棵节点树，用来记住"哪个格填了什么" | Word 的公式对象模型、`\prescript` 这种依赖引擎特性的写法 |
| 插入时序列化出的 `$…$` | 任何"先存成公式对象、导出再转"的中间态 |

**数据模型从第一行代码起就是 LaTeX 字符串**。你举的例子就是规格——**往左上格写个 `3`，确定后产物是 `{}^{3}`**，再与中心格拼成 `{}^{3}X`，包上 `$` 就是插入文档的内容（实测位置见 §7.5 第 8 条）。

#### 7.1.1 槽位递归：任何槽都能放任何范式节点

三张手绘图定下的结构（第三张是关键）：

| 图 | 结构 | 序列化 |
|---|---|---|
| 图 1 · 四角标 | 中心格 + 左上/左下/右上/右下四格（左右分布在中心两侧） | `{}^{左上}_{左下}中心^{右上}_{右下}` |
| 图 2 · 分数 | 上格 + 中线 + 下格 | `\frac{上}{下}` |
| 图 3 · **分数里的四角标** | 分数的下格本身又是一个四角标结构 | `\frac{a}{{}^{c}_{d}b}` |

图 3 说明的唯一规则：**槽是递归的。** 节点树的每个槽位可以填文本，也可以再放一个范式节点，深度不限（序列化自然递归，闸门只设一个防手滑的深度上限 20）。反方向同样成立——四角标的位置上也可以放分数、根号。

嵌套实测（`_probe_nest.cjs` + latex2mathml，2026-11-10）：`\frac{{}^{a}_{b}X}{c}`、`\frac{a}{{}^{c}_{d}b}`、`{}^{\frac{a}{b}}_{c}X`、`\sqrt[3]{\frac{a}{b}}`、`\sqrt{{}^{a}_{b}X}`、`\frac{\sqrt{a}}{\frac{b}{c}}`、`\sqrt{\frac{{}^{a}_{b}X}{\binom{n}{k}}}`、`{}^{\overline{ab}}_{c}X`、`\overline{\frac{a}{b}}`、`\left(\frac{a}{b}\right)` —— **KaTeX 10/10 PASS，latex2mathml 9/9 PASS**。画布渲染用真实 KaTeX 输出嵌入槽位（不是自己画近似形状），天然所见即所得。

现状：**没有入口。** 全文件搜「公式」只有排版面板的字号一栏（`:1389`）与 i18n 文案；正文公式目前只能手打 `$…$`。渲染管线已就绪（`:4373` 提取、`:4411` KaTeX），缺的只是输入方式。

### 7.4 画布 = 一棵节点树，节点数等于范式数

这是"零 LaTeX 输入"能成立的根本：**用户操作树，序列化是最后一步，用户看不见。**

```
root（contenteditable 行内流）
 ├─ text   "当"
 ├─ frac   { 分子:[text "a"], 分母:[text "b"] }          ← A2
 ├─ text   "="
 ├─ script { 左上:[text "3"], 左下:[], 中心:[text "X"], 右上:[text "2"], 右下:[] }  ← A1
 └─ sqrt   { 指数:[text "3"], 被开方:[text "x+1"] }      ← B1
```

**六个节点类型，与 §3.3 的范式表一一对应，不多一个：**

| 节点 | 对应范式 | 视觉形态 | 槽位 | 序列化 |
|---|---|---|---|---|
| `text` | — | 普通文字 | — | 见 §7.5 第 1、2 条 |
| `script` | **A1 四角标** | 中心 + 左上下 / 右上下 | 5 格 | `{}^{左上}_{左下}中心^{右上}_{右下}`，空槽省略 |
| `frac` | **A2 分数** | 上格 / 中线 / 下格 | 2 格 + 中线开关 | 开 → `\frac{a}{b}`；关 → `\binom{a}{b}` |
| `delim` | **A3 容器** | 左符 + 内部（单行或网格）+ 右符 | 每格 | `\left(…\right)` / `\begin{pmatrix}…\end{pmatrix}` 族 |
| `sqrt` | **B1 根号** | √ 钩 + 覆盖线 + 左外上方指数格 | 2 格 | `\sqrt[n]{x}`，无指数则 `\sqrt{x}` |
| `accent` | **B2 帽线** | 内容 + 正上方（或正下方）一个符号 | 1 格 + 符号参数 | 内置符号 → `\overline{x}` `\vec{x}` `\hat{x}` …；自定义符号 → `\overset{△}{x}` / `\underset{△}{x}` |

**这就是"不为单个符号建模板"的落实**：`\sum` `\int` `\lim` 不是节点类型，是 `script` 中心格的文字；`( )` `[ ]` `| |` `pmatrix` `cases` 不是节点类型，是 `delim` 的左右符参数；`\bar` `\tilde` `\dot` 不是节点类型，是 `accent` 的符号参数。**节点表里数得出来，就六个。**

### 7.5 序列化契约（确定性，逐条可测）

1. **文本分段**：格内文本按字符类型自动切——ASCII 字母/数字与 `+ - = < > ( ) [ ] | / ! , .` 原样作数学；中文、全角标点、其余非 ASCII 包进 `\text{…}`。例：`当x>0` → `\text{当}x>0`。
2. **特殊字符转义**：`\ { } $ % # & _ ^ ~` 逐个加反斜杠；容器槽内 `&` 作列分隔符，不转义。
3. **空槽省略**：一律不留 `{}` 空壳（`x^{}` 会渲染成空壳或报错）。
4. **嵌套上限 8 层**：超限拒绝插入并提示，防递归炸栈。
5. **插入前过闸门**：`katex.renderToString(tex,{throwOnError:true})` 跑一遍，抛错则不插入、toast 指出出错槽位。序列化器有 bug 也污染不到文档。
6. **函数名自动转正体**：`sin cos tan cot sec csc arcsin arccos arctan sinh cosh tanh log ln lg exp lim max min sup inf det gcd deg dim ker arg` 自动加反斜杠（`lim` → `\lim`）。**不加就把 `lim` 渲染成三个斜体字母 l·i·m**，视觉上直接是错的。
7. **必须带 `$`**：生成 `'$'+tex+'$'`，插入前断言首尾正好一个 `$`。
8. **前置角标（A1 的左格）拼法**：左上格 `a` + 左下格 `b` → 前缀 `{}^{a}_{b}`，再接中心格。
   - 只有左上：`{}^{3}X`
   - 只有左下：`{}_{4}X`
   - 两者都有：`{}^{3}_{4}X`

   **必须知道的位置事实**（`_probe_prescript.py`，Chromium DPR=2，28px 字号）：

   | 用例 | 角标盒 x | 中心盒 x | 结论 |
   |---|---|---|---|
   | `{}^{3}X` | 0（宽 14） | 14 | 角标占**左侧独立一列**，不压在 X 头顶 |
   | `{}_{4}X` | 0（宽 14） | 14 | 同上，只是纵向在下 |
   | `{}^{3}_{4}X` | 0（宽 14） | 14 | 左上 y=0、左下 y=20，左右夹住中心 |

   所以面板画布里的左上/左下格**必须画在中心格的左侧**，不能画在头顶——否则面板里看到"悬在左上"，插进文档变成"缩在左边"，就是所见非所得。这是 LaTeX 的语义，不是我的取舍。

   **中心格为空时前置角标悬空**：`{}^{3}` 单独也能渲染（实测 PASS，不报错），但出来就是一个漂着的小 3，没有附着对象。所以闸门加一条语义检查——**只有前置角标、中心格为空 → 拒绝插入**，toast 提示"角标需要有中心内容"。后置角标同理（`^{3}` 裸写同样能渲染，同样拦）。

9. **序列化失败一律不插入**：任何一条不满足（闸门抛错、嵌套超限、断言失败）→ 保持面板打开、toast 说明原因、光标停在问题槽位。绝不插入半成品。

### 7.9 Word 导出映射：走 OMML 正规写法 `m:sPre`（第七版重写，撤回方案 0）

主人实测：零代码时四角标在 Word 里也能显示，但那是"隐形定界符包空 base"的凑合结构，**不是 OMML 的正规写法**。转 docx 就要转成它正规的显示方案，否则转什么。定案：**用 `m:sPre`（Pre-Sub-Superscript，OMML 原生的前置上下标元素）**。

#### 现有规则（不动）

公式导出只认预览 DOM 上的 `data-tex`（原始 LaTeX，不含 `$`）→ `_append_omml`（`docx_export.py:888`）→ latex2mathml → 自有 MathML→OMML 转换器（`:77`）。上下标分支 `msub/msup/msubsup → sSub/sSup/sSubSup`（`:164-169`）、大运算符 nary（`:145-155`）——这些全保留，只在**空 base**这一种情况上分岔。

#### 关键结构事实（实测 MathML）

`{}^{3}_{4}X` 的 MathML 是：

```
<mrow>
  <msubsup><mrow/>  <mrow>4</mrow>  <mrow>3</mrow> </msubsup>   ← 空 base，只有角标
  <mi>X</mi>                                                    ← 中心是【兄弟节点】，不在 msubsup 里
</mrow>
```

所以正规映射的核心不是换元素名，而是**把后面的兄弟节点合并进 `m:sPre` 的 `m:e`**：

```
<m:sPre>                    ← 前置上下标，Word 公式工具栏里"上下标前置"就是这个
  <m:e><m:r>X</m:r></m:e>   ← 兄弟节点移进来
  <m:sub>4</m:sub>
  <m:sup>3</m:sup>
</m:sPre>
```

（子元素序 e、sub、sup，与 sSubSup 同序，与 ECMA-376 CT_SPre 一致；实现后用 Word 实开验证一次即钉死。）

#### 转换算法（`mathml_to_omml` 内，约 35 行）

| 步骤 | 内容 |
|---|---|
| 1 | 空检测：`msub/msup/msubsup` 的第一个孩子是**空 mrow**（无文本无子元素）→ 进入本分支；否则走原有 sSub/sSup/sSubSup |
| 2 | **兄弟合并**：改造 mrow 类父节点的遍历循环——遇到空 base 上下标节点且**后面还有兄弟**时，把兄弟转出的 OMML 塞进 `m:e`、一次吞掉两个节点 |
| 3 | 三种形态：`msubsup` 空底 → sPre(sub=下, sup=上)；`msup` 空底 → sPre(sub=空, sup=上)；`msub` 空底 → sPre(sub=下, sup=空)。缺的一侧留空 `m:sub`/`m:sup`（nary 分支已有空 `m:e` 先例，schema 允许空参数） |
| 4 | 空底上下标**后面没有兄弟**（如手打的 `{}^{3}`）：保持现有行为不崩（面板闸门本来也拒绝插入这种） |
| 5 | 与 nary 分支互不干扰：nary 判的是 base 是大运算符，空 base 永远不命中 nary |

#### 回归与验收

- 新增用例：`{}^{3}_{4}X`、`{}^{3}X`、`{}_{i}X` 三形态 + 嵌套 `rac{{}^{a}_{b}X}{c}`、`{}^{rac{a}{b}}_{c}X`，导出最小 docx。
- 机器侧：python-docx 重新打开验证 zip/XML 完整（防"文件损坏"，v2.4.9 根式分支的老坑有先例）。
- 人工侧：Word 打开确认角标**在中心左侧**、结构是 Word 公式工具栏可再编辑的真上下标（点开公式能看到 sPre 结构），不是死的隐形括号。
- 全量回归：现有 docx 导出用例跑一遍（mrow→无括号 m:d 的改造在父节点遍历，必须证明没误伤普通公式）。

### 11.1 先把「打开按钮」讲清楚（对应第 4 条）

**白话流程（先流程，后证据）**：

1. 从资源管理器复制一个文件（pdf / xlsx / csv…）粘进编辑区；
2. 编辑器**不把文件名写成 markdown 链接**，而是把文件字节复制进本文档同名的 `.assets` 目录（`.smd` 文档则进包内 `assets/`），正文里只留一行写着相对路径的「数据点」；
3. 这一行在**渲染区**会变成显示相对路径的一小块，**旁边挂一枚「打开」按钮** —— 这就是主人记得的那一枚；
4. 点「打开」→ 服务端先检查这个路径必须落在本文档资产目录内（防别人发来的文档诱导双击运行任意程序）→ 用系统关联程序打开这份副本 → 顺手把吃这份数据的执行点复位为「待运行」。

### 11.4 插入图片弹窗规格（网络 + 本地）

- **外壳**：复用 `#linkOverlay` 的 `.dlg-card` 骨架新建 `#imgOverlay`（不新写弹窗组件）。**必须同时补 `#imgOverlay[hidden]{display:none!important}`** —— 内联 `display:flex` 会压过 `[hidden]`，母版弹窗、链接弹窗、公式面板已连踩三次。

- **网络分支**：只接受 `http://` / `https://`，其余一律拒绝并 toast（fail-closed；不放行 `javascript:` / `data:` / 协议相对地址）。空地址或只填了 `https://` 不插入。产出 `![说明](地址)`，走 `replaceAtCaret`（带滚动快照）。`fixLocalImages` 对 `https?://` 原样放行（`:4727`），预览不会被改写成本地代理。

## 15:38 追记：安装包「关于与快捷键」资源缺失（发版链中止后修复）
