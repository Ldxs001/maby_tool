# low runner 数据形式规范（设计稿）

> 状态：**已实现（v2.6.0）**。本文是 `@@ MDE` 数据点语法与 run 类型契约的权威描述——后续讨论有变更先改本文再动代码。

## 设计原则

- **框架认结构，全部传 Python 原生类型**（str / list / dict / 嵌套 list）——data 经 stdin JSON 传子进程，原生类型直传；科学栈（numpy/pandas/xarray）转换放 run 里一行完成，框架层零三方依赖
- **写作友好**：数据长在正文里（行文 `(( ))` 抽取）、表格就是 Markdown 表格
- **fail-closed**：写错按普通文本显示，不炸文档、便于发现笔误
- **向后兼容**：现有形式（单值文本 / 单键值对 / 跨行长文本）行为分毫不变；`raw` 原文通道永远保留（逃生舱）
- 显性/隐性（`MDE_甲` / `MDE__甲`）与别名池机制对全部六形式一视同仁

## 一、六种数据形式

### 1. 单值文本（现有，不变）

`@@ MDE_甲{文本}` → `vals` 通道 += `"文本"`（str）

跨行长文本、`\n` 保留（现有能力）。显示：原文。

### 2. 单键值对（现有，不变）

`@@ MDE_甲{k == v}` → `kv` 通道 `k = "v"`（str）

显示：v。

### 3. 纯值向量（新）

两种写法，结果相同：

- **直写**：`@@ MDE_甲{8%,1.5%,0.6%}` → `vals += ["8%","1.5%","0.6%"]`
- **行文抽取**：`@@ MDE_甲{2025年，我国GDP总体上涨((8%))，同比上涨((1.5%))，是疫情以来第一次出现大于((0.6%))的上涨。}` → `vals += ["8%","1.5%","0.6%"]`

规则：

- 直写仅限**单行**；半角 `,` = 分隔符；值内要写逗号 → 全角 `，` 或改用行文形式
- **跨行 body 一律是文本**（形式 1，保护现有长文本能力）
- 行文形式中逗号是普通文字，抽取只认 `(( ))` 标记
- 显示：直写 = 原文；行文 = 全文**去掉 `(( ))` 标记**后的干净句子（待确认⑥）

### 4. 键值对向量（新）

两种写法，结果相同：

- **直写**：`@@ MDE_甲{A == 8%, B == 1.5%, C == 0.6%}` → `kv` 合并 `{A:"8%", B:"1.5%", C:"0.6%"}`
- **行文抽取**：`@@ MDE_甲{2025年，…上涨((A == 8%))，…((B == 1.5%))，…大于((C == 0.6%))的上涨。}` → 同上

规则：

- 直写仅限单行；每个逗号段必须含 `==`，否则 fail-closed
- 值内要写逗号 → 全角或行文形式
- 显示：直写 = 各 v 以 `、` 相连；行文 = 去标记全文（待确认⑥）

### 5. 二维表格 `:2(rxc)`（新）

```
@@ MDE_甲:2(2x2){
|职务|名称|年龄|
|:-|:-|:-|
|总经理|tony|59|
|秘书|lily|18|
}
```

→ `vals += [["tony","59"],["lily","18"]]`

坐标规则：

- `:2` = 二维；`(r x c)` 为 **1-based 起始坐标**：数据区 = 第 r 行第 c 列起、取到表格末尾
- **分隔行（`|:-|:-|` 类）是结构行：不计入行号、不进输出**——第 1 行 = 表头行，第 2 行 = 第一条数据行（示例 `(2x2)`：跳过表头行与"职务"列 → 名称/年龄两列两条数据）
- 单元格一律 str（数字也是）；空单元格 = `""`；行内列数不足按 `""` 补齐（容忍参差行）
- 单元格内 `\|` = 字面竖线（Markdown 惯例）
- 显示（v2.6.12 改）：**按原文渲染成真表格**——body 里的表格行原样交给 markdown 渲染器，屏幕上看到的就是一张普通表格；标记行 `@@ MDE_甲:2(){`、坐标、`}` 都不显示。**坐标裁剪只作用于数据**（`data-dp-val`），屏幕永远显示整张原表——所见即所写，免得有人看着裁剩的子表以为原文写少了。缺分隔行（只写数据行）时渲染前补一行结构行，可见字符不动。显性/隐性的**唯一差别**就是 `_` 与 `__`：隐性整块不渲染（导出时整块剔除）

### 6. 三维表格 `:3(rxc)`（新）

多张二维表以**空行分隔**，每张表按同一坐标裁剪：

```
@@ MDE_甲:3(2x2){
|职务|名称|年龄|
|:-|:-|:-|
|总经理|tony|59|
|秘书|lily|18|

|职务|名称|年龄|
|:-|:-|:-|
|总经理|tony|48|
|秘书|lily|18|
}
```

→ `vals += [ [["tony","59"],["lily","18"]], [["tony","48"],["lily","18"]] ]`

（**二维表的列表** = 三层嵌套；用户示例原文输出有一处层级笔误，按此为准——待确认①）

- 张数 = 实际表格数（不另行声明）；各表形状允许不一致（纯 list 容忍参差；`np.array` 需规则形状）
- 显示（v2.6.12 改）：**按原文渲染成多张真表格**——空行分隔的每张表各渲染成一张，屏幕上看到几张表就是数据里有几层；标记行与 `}` 不显示，坐标裁剪同样只作用于数据

## 二、类型契约（run 收到什么——就这些，没有别的）

| 通道 | 类型 | 内容 |
|---|---|---|
| `data['kv']` | **dict** | 值永远 str（数字也是 str，运算前自己转） |
| `data['vals']` | **list** | 元素按文档出现顺序：str（单值）/ list[str]（纯值向量）/ 嵌套 list（二维表）/ 三层嵌套 list（三维块） |
| `data['raw']` | **list** | 数据点原文（str，逃生舱，不动） |

**需要其他结构自行转换（各一行）**：

- `np.array(嵌套list)` → array
- `pd.DataFrame(二维)` / `pd.Series(dict)` → 表格 / 序列
- 三维：`np.array()` 后 `xr.DataArray`

三方包已装（runtime/pylibs）才用；未装在代码顶部注释写明需安装的包名。

## 三、fail-closed 清单

- `:N` 非 2/3；坐标缺失 / 非正整数 / 越界
- 键值向量直写里某逗号段无 `==`
- `((` 无 `))` 闭合；`(( ))` 内为空
- 直写与 `(( ))` 混用（如 `{a,b ((c)) d}`）
- 同一行文内 `((k == v))` 与 `((v))` 混用
- `:2` 块内出现空行分隔的多张表（多表是 `:3` 专属）
- 表格行非 `|…|…|` 形态

→ 以上任一：**整个数据点按普通文本渲染**（不炸文档）

## 四、LLM 生成契约（`_LR_LLM_SYS` 重写要点）

> 前端传入 data 固定为这些类型，别无其他：
> - `data['kv']` 是 dict（值 str）——数字运算前先 int()/float()
> - `data['vals']` 是 list——元素可能是 str、list（纯值向量）、嵌套 list（二维表）、三层嵌套（三维块）
> - `data['raw']` 是原文 list
> 按这些类型直接写代码；需要 array/DataFrame 等结构自行转换（`np.array(x)` / `pd.DataFrame(x)` 各一行；三方包用户自装 pylibs）。

原 D 类"角色映射纪律"随之简化（结构由框架给出、代码直接消费）；中文词频（text.count 禁 split）等纪律保留。

## 六、定稿记录（2026-10-23 用户拍板）

1. **三维输出** = `[[二维表A],[二维表B]]`（三层嵌套）——用户确认（原示例为笔误）
2. **行文形式显示** = 去掉 `(( ))` 标记后的干净句子
3. **坐标行号不计分隔行**：第 1 行 = 表头行，第 2 行 = 第一条数据行
4. **`(rxc)` 括号必填、坐标可缺省**：`() `空括号 = 全表（1x1 起始）；有坐标才填数字——保证代码结构完整
5. `:2` 块内多表 → fail-closed（多表是 `:3` 专属）
6. 直写与 `(( ))` 行文混用 → fail-closed

## 七、全局执行 `{global p}`（设计定稿，待实现）

### 场景（用户举例）

run 功能"自动上标引用序号"：全文散布标记（如 `'''p`），run 计算每个标记的替换内容（序号递增），框架替换：

```
十级台风只出现于模拟实验中'''p，这是1938年古某某学家瞎胡扯设计的，
他利用一百万只气球同时造成扰动'''p，...
→
十级台风只出现于模拟实验中^{[1]}，这是1938年古某某学家瞎胡扯设计的，
他利用一百万只气球同时造成扰动^{[2]}，...
```

### 执行点语法

`@@ MDE import xxx is zzz{global p}` / `@@ MDE from xxx import yyy is zzz{global p}`

- `{global p}`：声明本执行点处理全文中名为 `p` 的标记（可与 `is zzz` 数据池并存：`is` 池照常提供 kv/vals，`global` 额外提供 marks）
- 执行点自身渲染：不可见（它是"指令"不是内容）

### 标记语法（定稿）

- 标记 = **`'''`（三单引号）**，后跟标记名：`'''p`；标记名为单词（`pwqztd`、`dfdfdf` 等任意）
- **`` ``` `` 系列（三反引号）一律不可用**：是代码围栏语法，`` ```p `` 会被 parser 解析为"语言 p 的代码块开头"吞掉后续文本——用户示例中两种混用仅为示意，实现按 `'''` 一种
- 标记识别规则：正文中 `'''名称` 实例（代码块/行内代码内的 `'''` 不识别——那是内容）；`data['marks']` 每项含标记名与所在句上下文，怎么用是 run 的事（框架只管识别与传递）

### 核心机制（方案 B：框架收集标记，run 只决定替换什么）

1. **框架全文扫描** 该标记的所有实例，按文档顺序传入：
   `data['marks'] = [{'mark':'p', 'ctx':'……模拟实验中'}, …]`
2. **run 返回等长列表** `['^{[1]}', '^{[2]}', …]`——每个元素替换对应位置的标记
3. **框架安全替换**：全文其他部分 run 碰不到（零破坏风险）；替换文本经行内 markdown 渲染（与现有执行点返回值同待遇）
4. 标记增删 → marks 指纹变化 → 执行点自动重跑（现有数据指纹机制天然支持）
5. **返回数量与标记数不符 → 按执行失败处理**：执行点显示错误、标记保持原文——与 run 抛异常同一条失败路径，无任何特殊逻辑

### 运行与显示（定稿）

- 运行标志都在执行点上——**与普通执行点同一套**：立即/等待/手动模式、▶ 重试、导出关口全部沿用；没有单独的"全局运行"概念
- 未运行时标记显示**原文 `'''p`**
- 多个 global 执行点（不同标记名）：**各自独立**扫描各自的标记、各自替换（用的不是同一功能，互不相干）

## 八、实现补充决议（v2.6.0 施工时定稿）

1. **直写与行文混用的检测**：行文形式（含 `(( ))`）的散文部分出现**半角 `,`** 或 `==` 即 fail——用户行文示例的散文全部使用全角标点，半角逗号/等号只可能来自直写语法（`'a, ((b))'`、`'x == 1 ((b))'`）。
2. **单键值对值含半角逗号 → fail**：`{备注 == 内部,口径}` 按向量分段规则第二段无 `==` → fail-closed（值内要逗号：全角 `，` 或行文形式）。规范第四节"值内逗号是文本（向后兼容）"仅适用于无逗号 body 的旧行为，含半角逗号即进入向量语义。
3. **连续数据点行**：段落收集遇未闭合的 MDE 起始行（`@@ MDE_x:2(2x2){` 后无 `}`）即断段——否则连续数据点行把表格语法吞进段落漏成明文。
4. **global 执行点不可见性走 CSS**（`.mde-run-global{display:none}`、`[data-done=err]`/`[data-pending]` 可见）——不写内联 style（内联 display:none 盖过一切 CSS，失败态红字会被藏住）。
5. **服务端 driver 返回 list 透传**：run 返回 list → `list[str]` 逐项 JSON 化（global 契约）；其他非 str 类型仍 `str()` 化。

## 九、多角色数据与「只许选不许造」（v2.6.6 定稿）

**一个角色一组数据点。** 代码要几样**不同角色**的东西（正文、关键词、阈值、列名…），就写几行数据点，至少两组，每行注明角色；两行（多行）用**同一个池名**合并，代码按类型分派。

```
@@ MDE_甲{今天遇到一个外国人，他对我说"你好"，我也回应他"你好"。…他说的竟然是中国话。}
@@ MDE_甲{你好,中国话}
@@ MDE from wordcount import count is 甲
```

- 第一行形式1（`vals` += str，正文）；第二行形式3（`vals` += list[str]，关键词）。代码按 `isinstance(x, list)` 分派，关键词增删不改代码。
- 键值对同样可行，但**值里只能用全角 `，`／顿号**：`@@ MDE_甲{词 == 你好、中国话}` → `kv['词'] = '你好、中国话'`，代码自行按顿号切分；写半角逗号会进入向量分段语义 → fail-closed。

**一行兼两种角色做不到**（不是写法选择，是契约限制）：

- 行文抽取 `(( ))` 只把括号里的**值**交出去，句子本身只用于显示（`disp`），**不进 `data`**；
- 半角逗号切分只交出一串**值**，交不出整句。

**`(( ))` 的唯一用途**：值本来就长在长文里，想让句子照常读、又把值抽出来算（`@@ MDE_甲{…上涨((8%))，同比上涨((1.5%))}`）。独立的值一律用形式3，**禁止**把 `(( ))` 当向量容器（`{((你好))、((中国话))}`）。

**run 代码的输入边界（硬约束）**：一切输入只能来自数据点四通道。禁止 `input()`／`sys.stdin`（后台子进程无人按键，当场 `EOFError`，且提示语写进 stdout 会毁掉 JSON 回包）；禁止 `print`（stdout 被框架独占传结果）。数据点缺角色时，唯一合法响应是返回一句说明文字（如 `'未找到关键词，请在数据点里写一行词列表，如 {你好,中国话}'`），不提问、不用 `0` 或空串冒充结果。

**键名边界**：禁止**猜**用户的键名（`if k in ['苹果','A','B']`）；代码**自己在用法说明里约定**的键名（如 `正文`／`词`）可以按名取，但必须原样写进用法说明让用户照着填。

### 9.1 选形式看需求语义，不看像哪个正例（v2.6.7 定稿）

| 需求说的是 | 该用的形式 | 数据点行数 |
|---|---|---|
| "我标出的／圈出的／文中这几处／其中……"（要的是**原文里的片段**） | 行文抽取 `(( ))` | 1 行（片段就是唯一角色） |
| "这些数／每一项／这些值"（彼此独立、没有名字） | 形式3 纯值向量 | 1 行 |
| "每个名字对应的值" | 形式2／4 | 1 行 |
| "这段文字／整段／正文是什么" | 形式1 单值文本 | 1 行 |
| "表里／第几行第几列" | 形式5／6 表格 | 1 行 |
| 同时要**两样不同角色**（如"在某段正文里查若干关键词"：正文 + 词表） | 各自选一行 | 每角色 1 行 |

**行文抽取的落地形状**：`(( ))` 圈出的片段在 `vals` 里落成**一个 list 元素**（与形式3 同形）——
`@@ MDE_甲{今天遇到一个((外国人))，…我们((聊了))一下午，说了((很多各自的见闻))…}`
→ `vals = [["外国人", "聊了", "很多各自的见闻"]]`，句子本身只用于显示、不进 `data`。
代码必须走 `isinstance(x, list)` 那一支，按 `str` 取会得到空。

**正例是标本，不是模板**：每个正例只对应它自己那条需求的语义，套到别的需求上就是错（照抄"正文+词表"两组模板去写"合并标出片段"，就是典型错例）。
## 十、执行点返回值的渲染（v2.7.0 定稿）

**规矩一句话**：run 返回什么形状，前端就认什么形状；不认的一律原样当文字，不猜。

| run 返回 | 前端怎么认 | 显示成 |
|---|---|---|
| 单行 `str` | 行内 markdown（粗体／斜体／行内码／链接／图片） | 跟在执行点原位的一段文字 |
| 多行 `str`（字符串里含真换行 `\n`） | 逐行切分，每行仍走行内 markdown | 多行文字；容器转块级，不吃段落首行缩进 |
| 表格块 | 某行含 `\|` 且**下一行是分隔行** | 真表格 |
| `list`（非 global） | 逐元素 `str()` 后逗号连接 | 一行文字（global 执行点见第七节） |

**表格的判定**（与正文表格同一函数、同一口径）：某行含 `|`，紧跟的下一行只由 `|` `-` `:` 和空格组成且含 `-`。分隔行**只定列数与对齐，自身不渲染**。

```python
return "|x|x|\n|-|-|\n|y|y|\n|z|z|"
```

→ 表头 `x | x`，两行数据 `y | y`、`z | z`。

- 对齐沿用 GFM：`---` 左、`---:` 右、`:---:` 居中。
- 单元格内的竖线写 `\|`。
- 表格块之间用空行隔开，一次可返回多张表；表格前后的普通行按文字渲染。
- **不支持**：单元格内换行、跨行跨列合并（GFM 边界，不是实现取舍）。
- 不写分隔行 → 不进表格分支，原样当文字（fail-closed）。

**图片（v2.8 起）**：run 的 `cwd` 就是本文档资产目录，所以 `save('x.png')` 之后返回 `![](x.png)` 即可显示、可导出、进 `.smd` 包。返回 `![](<名>.assets/x.png)` 这种带前缀写法同样认。旧写法（落 `run_cache` 返回文件名）保留为兜底，但那份不会被清理也带不走。

**结果里不生成数据点**：返回文本中出现 `@@ MDE…` 或 `'''标记`，只当普通文字。理由是可验证的——否则 run 读进来的一段文件内容里若恰好有 `@@ MDE_甲{…}`，会在预览区反向生成数据点并被收进池子，等于"一个 run 的输出能改另一个 run 的输入"。

**导出口径**：docx 导出会把执行点结果里的表格提升到段落之后（Word 不认段内表格），导出为真 `w:tbl`；HTML 导出保持嵌套结构，浏览器正常渲染。

## 十一、外部文件引用（v2.8.0 定稿）

**一句话**：框架只负责让文件有个 run 能 `open()` 的地址，**不解析任何文件**。xlsx 怎么读、pdf 怎么拆，是 run 作者的事，要三方包自己装到 `runtime/pylibs`。

### 11.1 粘贴产生什么

从资源管理器复制文件 → 编辑区 `Ctrl+V`：

| 环节 | 规则 |
|---|---|
| 判定 | 剪贴板项 `kind === 'file'`（文字、网页图片链接没有这个标记，不进本分支） |
| 落盘 | 字节复制进本文档资产目录：`.md` → `<文档名>.assets/`，`.smd` → 包内 `assets/` |
| 文件名 | **保留原名**（与图片的时间戳命名不同）；`,` `=` `{` `}` 与换行换成 `_`；重名不同内容加 `__<4位哈希>` 不覆盖 |
| 上限 | 单文件 20MB，超限拒绝并提示（不静默截断） |
| 插入 | 一行数据点，**池前缀照抄文档里最近一个数据点**（`@@ MDE_` / `@@ MDE__` / `@@ MDE_甲` / `@@ MDE__甲`）；无先例用 `@@ MDE_{` |

```
@@ MDE_甲{销售数据 == <文档名>.assets/销售数据.csv}
```

值永远是**相对路径**（可迁移）；文档里不出现盘符、不出现 `file://`。

### 11.2 run 收到什么

`/api/run` 请求体带 `mdPath`。服务端在把 `data` 交给子进程之前：

1. 遍历 `kv`（值）、`vals`（逐元素，含嵌套）、`raw`（逐条）；
2. 命中形如 `<名>.assets/xxx` 或 `assets/xxx` 且**文件真实存在**的字符串 → 换成绝对路径；
3. 只认落在文档目录内的路径（`../` 穿越一律不展开，原样交给 run，让它 fail 得看得见）。

run 侧不看别的：`open(data['kv']['销售数据'], 'rb')`。

### 11.3 run 的当前目录

子进程 `cwd` = **本文档资产目录**（v2.8 起）。所以：

- `save('x.png')` / `open('x.png','wb')` 直接落在能跟着文档走的地方；
- 相对引用值（`<名>.assets/x`）虽然以文档目录为基准，但展开后是绝对路径，run 不需要知道基准是什么；
- 文档未保存时回落 `run_cache`（旧行为）；
- 资产目录若因执行而临时创建、跑完仍为空 → 自动删除，不留空目录。

### 11.4 「打开」按钮与执行点复位

- 显性引用的值形如 `*.assets/文件` 时，数据点后挂「打开」按钮 → `POST /api/open-ref`；
- 服务端做目录白名单校验（必须落在本文档资产目录内，否则拒绝），通过后交系统关联程序打开；
- 打开成功后，吃该池的执行点全部复位为「待运行」，并删掉对应结果缓存——**改了文件就该重算，不拿旧结果冒充**；
- 导入/导出：docx 与 HTML 导出都剥离该按钮；
- 隐性引用（`__`）没有渲染位置，因此不挂按钮；
- **路径允许带空格**：文档名带空格时资产目录名也带空格（`MDEditor 使用指南.assets/x.csv`），判定只排除换行/制表符与绝对路径，不按空白一律否掉——否则这类文档永远不出按钮。

### 11.5 明确不做

不做解析、不引三方包、不做原文件同步、不做来源路径记录、不做 `http(s)://` 远程引用、不新增第七种数据形式。
