## 0. 一句话

**元数据只有两条互斥通道，二选一，都不参与导出，只在预览区看得见。** 剩下是档案文件与排版面板外壳重排。

---

## 1. 三条硬规矩（先立规矩再谈实现）

1. **`@@` 后面只跟英文小写标识符**，家族现有 `begin / end / fill / color / full / page / blank / caption / MDE`。新指令定名 **`@@ meta`**。
2. **元数据值不进正文**。自有模式的唯一真源是档案文件；正文里只有一行 `@@ meta` 作**位置锚点**，不带任何值。
3. **元数据区只在预览出现**。打印、Word、HTML 导出都不出（HTML 导出另说，见 §5）。

---

## 2. 两条通道

### 通道 A · 兼容模式（读别人的文档）

**触发判据（四条全中，任一不中整段不认）**

1. **首行**恰为 `---`（允许尾随空白，允许开头一个 UTF-8 BOM）；
2. 存在闭合 `---`，且两者之间**没有任何空行**；
3. 闭合前**至少一行**匹配 `^[A-Za-z_][A-Za-z0-9_\-. ]*[ \t]*:`；
4. **必须是首行**——`---` 前面有任何内容（哪怕一行空行）都不算，按普通文本走原路径。

第 3 条是防误判闸：`--- / 第一章 / ---` 这种装饰横线组不会被吞成元数据区。

**不认时**：走原有 hr + 段落路径，一字不吞，报诊断 `D301 front matter 结构不合法（有空行 / 无键值行 / 不在首行），已按普通文本渲染`。

**解析范围**：只做平铺 `key: value`，不碰 YAML 的嵌套、列表、多行折叠。值两侧成对引号剥离。不匹配 `key: value` 的行**按原文行输出**（`.mde-fm-raw`），零吞字。

**渲染位置**：固定在文首（因为它本来就在文首）。

### 通道 B · 自有模式（我们自己的档案）

**触发条件（两个同时满足才出区域）**

1. 正文存在一行 `@@ meta`（占位锚点）；
2. 档案文件里有**至少一个非空字段**。

**数据源**：`assets/.mde/zero.json`（创建者快照）+ `assets/.mde/up.md`（修改履历）合并出当前值。

**渲染位置**：`@@ meta` 那一行所在的位置。

**没有数据就不出区域**——不占位、不出虚线框、不出任何提示条。`@@ meta` 行静默无输出（与 `@@ blank` 把整行吃掉是同一个语义）。

### 冲突处置

首行有合法 front matter **且**正文有 `@@ meta` → **两条都不渲染**，在文首出一条红色提示条：

> 元数据冲突：本文档同时存在 YAML front matter 与 `@@ meta`。二者只能选其一——删掉首行的 `---` 块，或删掉 `@@ meta` 行。

不再自作主张挑一个渲染。判断权在人。

## 3. 档案文件

```
<stem>.assets/.mde/zero.json   创建者元数据 · Hidden + ReadOnly · 建档时写一次，此后永不修改
<stem>.assets/.mde/up.md       修改履历 · 不设任何属性 · 追加式
.smd 包内：assets/.mde/zero.json、assets/.mde/up.md
```

`zero.json`：

```json
{
  "format": 1,
  "created": "2026-10-30T23:20:11+08:00",
  "creator": { "by": "MDEditor 2.23.0" },
  "fields": { "title": "", "author": "", "date": "", "tags": "", "note": "" }
}
```

- **不自动收集机器名、用户名、路径**——`creator.by` 只写编辑器版本，作者字段由人填。隐私优先。
- `up.md` 一行一条，人可读、可手改：

```
- 2026-10-30 23:24 · title：`` → `我写故我播`
- 2026-10-30 23:26 · author：`` → `wUwproject`
```

**"只读"保护的是什么**：防手滑、防外部工具误改，不是安全边界。程序只在建档时写一次，之后任何保存路径都不碰它，所以只读位不影响日常存盘。唯一需要解位的场景是"up 在而 zero 丢了要重建"——那种情况提示人手动处理，**不偷偷解位改写**。

## 5. 出口矩阵

| 出口 | 通道 A（front matter） | 通道 B（档案元数据区） | 冲突提示条 |
|---|---|---|---|
| **预览** | 渲染成元数据区 | 渲染成元数据区 | 渲染 |
| 打印 / 分页 PDF | 不出 | 不出 | 不出 |
| Word（.docx） | 不出 | 不出 | 不出 |
| HTML 导出 | 原样保留在文件头，**不渲染** | 不出 | 不出 |

实现方式：渲染时给元数据区打 `data-mde-zone="a|b"`，三个导出出口在取 bodyHtml 之前把带该属性的节点删掉；HTML 导出另把 A 通道的原文还原成文本节点放在 body 最前。

> **这一条是我的理解**：`html导出作为头不渲染` = 导出的 HTML 里 front matter 原文还在最前面（谁拿去做二次处理都还在），但不给它任何视觉样式。若你要的是"HTML 导出里彻底不出现"，一句话我改。

## 6. 总开关

排版面板「元数据」卡片顶部一个开关：**显示元数据区**，默认**开**。

- 开：通道 A / B 按 §2 判据正常出区域；
- 关：两条通道都不出区域，`@@ meta` 行静默无输出、不报错。

> **默认开的理由**：需求 1 要的是"别人给我的带 front matter 的 md 打开就能看"，默认关的话这条等于没做。若你要的是默认关（新功能默认不打扰），一句话我改。

## 7. 排版面板输入框与新建插入

### 7.1 输入框（5 个，全可选，全空不建档）

**标题 / 作者 / 日期 / 标签 / 备注**

点「应用」时按文档现状路由，写成一条规则：**输入框是统一入口，落到哪种载体由文档现状决定**。

| 文档现状 | 写到哪里 |
|---|---|
| 首行有合法 front matter | 原地改 front matter 对应键的值；没这个键就不新增（不改人的文件结构） |
| 有 `@@ meta`、无 front matter | 追加进 `up.md`；档案不存在则先建 `zero.json` |
| 两者都没有 | 先在文首插入一行 `@@ meta`，再建档案 |

存量老文件不迁移（"老文件我们不管"）——但只要它在面板里被写过一次，就自然进入通道 B。

### 7.2 新建自动插入

`newDoc()` 由 `setText('')` 改为 `setText('@@ meta\n\n')`，光标落第二行。

新建文档此刻还没有档案，所以 `@@ meta` 无输出——**正是"没数据就没区域"**。等人在面板里填了第一个字段，区域才出现。

### 7.3 指令解析落点

- 主体判定：`markdown-editor.html:803` `@@ blank` 判定旁边加 `@@ meta`（行级、无参、必须独占一行，不成行则按原文露出）。
- 需同步登记进"含 `@@` 的段落不得被吞"白名单：`:1329`、`:2149`、`:2153`、`:2165` 四处正则的 `(begin|end|caption|blank)` 补上 `meta`，否则 `@@ meta` 落在段中间会触发诊断误报。
- 多个 `@@ meta`：只认第一个，其余静默跳过并报 `D302 重复的 @@ meta 已忽略`。

### 7.4 数据怎么进渲染器（硬约束）

渲染函数是同步的，不能在渲染途中去后端读文件。做法：`/api/file`、`/api/save-as` 的响应体加 `meta` 字段，前端存 `window.__MDE_META__`，渲染时同步读——与既有缩进参数 `window.__IND_PX__` 同一种做法。
